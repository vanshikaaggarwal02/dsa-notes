The pattern: use the ordering to throw away half the tree

In a BST every value in the left subtree is smaller than the node, and every value in the right subtree is larger. So at each node you go left or right, never both, and a lookup takes O(height). An inorder traversal gives sorted order, which turns many problems (kth smallest, recover, two sum) into “do it on a sorted list”.

Watch for: validating a BST needs a value range passed down, not just a comparison with the parent. A skewed tree makes height n, so O(height) becomes O(n).
